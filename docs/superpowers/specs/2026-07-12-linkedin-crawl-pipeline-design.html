LinkedIn Profile Crawl Pipeline

2026-07-12 Status: Design (chờ duyệt) D:\workspace\linkedin-profile-search
Mục tiêu Crawl profile LinkedIn từ Apify (harvestapi/linkedin-profile-search) theo bộ lọc, lưu hết thông tin vào Postgres, đảm bảo mỗi người = 1 bản ghi duy nhất (enrich chứ không nhân bản), có job runner resume được, theo dõi throughput và dashboard web local.

01

Mục tiêu

Thu thập profile LinkedIn theo tiêu chí lọc (chức danh, địa điểm, công ty, ngành...), lưu toàn bộ thông tin, chống trùng lặp khi crawl (kể cả nhiều nguồn về sau), và giám sát được luồng crawl.

02

Phạm vi

Trong phạm vi

  • 1 nguồn: harvestapi (search theo filter)
  • Postgres trong Docker
  • 1 bảng data person (chi tiết để JSONB) + 2 bảng vận hành
  • Dedup theo slug chuẩn hóa (UNIQUE) + enrich
  • Job runner resume + checkpoint
  • Metrics throughput + dashboard FastAPI + Chart.js
  • Email = cột optional (chưa crawl)

Ngoài phạm vi (chừa chỗ mở rộng)

  • Fuzzy matching — giữ sẵn cột norm_name/norm_company, bật sau không cần migrate lại
  • Email enrichment
  • Nhiều nguồn khác (Apollo/PDL/Bright Data) — kiến trúc adapter cho phép thêm
  • Lên lịch định kỳ (scheduling)

04

Kiến trúc

Apify (harvestapi) --raw items--> SourceAdapter (normalize) --> CanonicalProfile --> Ingest Engine (match slug -> INSERT | ENRICH | needs_review) --> Postgres(person) Job Runner (run lifecycle, checkpoint, ghi metrics) --> crawl_run / run_metric Dashboard (FastAPI + Chart.js) đọc DB
  • SourceAdapter — biến raw record của 1 nguồn thành CanonicalProfile. Thêm nguồn = thêm adapter.
  • Normalizer — URL to slug, tên/công ty to norm_*, tính content_hash.
  • Ingest Engine — quyết định insert/enrich, merge JSONB, idempotent.
  • Job Runner — điều phối 1 run, checkpoint, ghi throughput.
  • DB layer — kết nối, helper upsert.
  • Dashboard / CLI (migrate, crawl, status).

Index: UNIQUE(linkedin_slug), index(current_company), GIN(data).

crawl_run (vận hành: theo dõi + resume)

id, source, status, params jsonb, apify_run_id, checkpoint jsonb (offset), started/finished_at, tổng: fetched / inserted / enriched / unchanged / errors.

run_metric (vận hành: chart throughput)

id, run_id FK, ts, processed, inserted, enriched, errors, rate_per_sec (rolling). Ghi mỗi K item / T giây.

06

Cơ chế dedup + enrich

Với mỗi CanonicalProfile P:

  • Chuẩn hóa URL to slug: bỏ https, www, subdomain quốc gia (vd vn.), dấu / cuối, query string, lowercase. VD https://vn.linkedin.com/in/An-Nguyen-123/?trk=x to an-nguyen-123.
  • Tính content_hash của payload (theo nguồn) để idempotent.
  • Khớp: có slug thì tra WHERE linkedin_slug = :slug; không có slug thì không đoán.

Quyết định:

  • INSERT khi không thấy (hoặc không slug thì kèm needs_review).
  • UNCHANGED khi content_hash đã có trong source_hashes[source].
  • ENRICH khi thấy và payload mới.

ENRICH (merge, không nhân bản)

  • Điền field còn thiếu (NULL/rỗng to giá trị mới). Không ghi đè giá trị đã có bằng rỗng.
  • Deep-merge data JSONB: mảng experience/education/skills gộp + khử trùng theo khóa tự nhiên (experience trùng nếu cùng company + title + khoảng thời gian).
  • Append source vào sources[], cập nhật source_hashes, last_enriched_at.

Idempotent toàn cục: chạy lại/resume cùng payload to không tạo trùng (slug UNIQUE + content_hash).

07

Job runner + resume + throughput

  • 1 lần crawl = 1 crawl_run (params = filter + apify_run_id).
  • Iterate dataset Apify, upsert từng item, cập nhật checkpoint.offset định kỳ.
  • Crash/chạy lại cùng run id to resume từ checkpoint; idempotent nên reprocess an toàn.
  • Mỗi K item / T giây to ghi run_metric (rate_per_sec rolling = processed/elapsed).
08

Monitoring / Dashboard

FastAPI + 1 trang HTML + Chart.js inline (không service ngoài), đọc Postgres: danh sách run; chart throughput/giây; tổng inserted / enriched / unchanged / errors; tổng person + breakdown theo sources; số needs_review. CLI status in nhanh run mới nhất.

09

Stack & hạ tầng

  • Postgres 16 trong Docker (docker-compose, volume bền). pg_trgm/unaccent bật sẵn để dành fuzzy.
  • Python 3.12 (conda). Libs: apify-client, psycopg v3, pydantic, fastapi + uvicorn, python-dotenv.
  • Migration = file SQL + script nhẹ (không Alembic). Config: .env + config.json.

11

Error handling & Testing

Error handling: lỗi từng item không giết run (bắt to đếm errors to log to tiếp tục); lỗi Apify run to status=failed + giữ checkpoint; DB transient to retry ngắn.

Testing (TDD): unit test cho normalize (URL to slug các biến thể, content_hash ổn định); ingest (insert; enrich điền thiếu; không ghi đè bằng rỗng; deep-merge + khử trùng; idempotent; thiếu slug to needs_review). Dùng Postgres test (Docker) + rollback transaction mỗi test.
